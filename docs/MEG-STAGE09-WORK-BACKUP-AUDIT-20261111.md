## Achados do Work confirmados na comparação com scripts reais
1. **P0 Restore falso local:** a versão anterior aceitava host TCP loopback, suscetível a `PGHOSTADDR`, service files e túneis. Um erro aqui permitiria escrever em banco não isolado. **Corrigido no código da branch** com socket fixo `/var/run/postgresql/.s.PGSQL.5432`, exigência de socket PostgreSQL pertencente ao usuário Unix `postgres`, `PGREQUIREPEER=postgres`, `env -i` para eliminar variáveis libpq herdadas, conferência SQL `inet_server_addr() IS NULL` e somente base `meg_restore_drill` vazia. Script não aceita TCP nem senha/host remotos. A criação da base é atividade **manual local**.
2. **P0 Verificação TLS:** a versão anterior aceitava `PGSSLMODE=require`, que garante cifra mas não identifica o host. **Corrigido no código** para exigir `verify-full`, `PGSSLROOTCERT` real baixado do dashboard Supabase, host validado e cliente PostgreSQL major 17. O script descarta variáveis libpq que poderiam redirecionar o hostname. Fonte: https://supabase.com/docs/guides/platform/ssl-enforcement e https://supabase.com/docs/guides/database/psql .
3. **P0 Vault GET:** Work destacou formato de resposta não confirmado. Verificação posterior na referência oficial encontrou **JSON `{"root_key":"<64 hex>"}`** em https://supabase.com/docs/reference/api/v1-get-pgsodium-config . O parser original exigia uma string, logo rejeitaria resposta legítima. **Corrigido** para validar `root_key` em objeto JSON; foram acrescentados limites de duração/tamanho e bloqueio de redirecionamentos com token. A API continua experimental/Beta, possivelmente requer privilégio alto; **não foi chamada**, não foi lido segredo nem executado PUT.
4. **P1 Metadados e privilégios:** o dump lógico `pg_dump --no-owner --no-privileges --no-tablespaces` não cobre roles globais, ownership, ACLs e parâmetros da plataforma. A mesma instalação de PostgreSQL não garante restauração funcional do serviço Supabase. Vault requer chave-raiz independente. **Pendente** inventariar configurações e planejar restore de projeto completo, com custo e autorização.
5. **P1 Senhas e mídia:** `PGPASSWORD` transitória do processo não é tão segura quanto conexão por papel de leitura e mecanismo protegido de segredo; permissões de diretório, recuperação `age`, assinatura/guarda de hash independente e retenção exigem controles adicionais. `umask 077` sozinho não fecha permissões já existentes. **Corrigido no código** bloqueio de diretório acessível a grupo/outros; gestão de credenciais/offsite continua pendente.
6. **P1 Testes reproduzíveis:** antes, a CI principal PG17 fazia `pg_dump|age|pg_restore` manual, mas **não chamava o script de restauração**. Workflow alterado para executar o script real em contêiner PostgreSQL 17 com dados fictícios, verificando PK/FK, identidade/sequence e índice, sem conexão a produção. O script de exportação exige host Supabase real intencionalmente e por isso só é testado com `psql/pg_dump` falsos, além do ensaio PG17 bruto. Não atribuir prova de ponta a ponta do backup de produção à CI.
